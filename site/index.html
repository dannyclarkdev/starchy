Find the layout bugs between your breakpoints.

starchy sweeps your page across every width from 1920px to 320px, finds the exact pixel where the layout changes, and flags the changes that are bugs.

npx starchy your-site.com

Checks

What counts as a problem

Every problem comes with the width range where it happens and the element that causes it. Identical problems on repeated elements are grouped into one row.

page-overflow

Horizontal scroll

The page is wider than the screen. starchy names the element that causes it: it hides each candidate and checks if the scroll width shrinks.

overlap

Overlap

In-flow sibling elements overlap each other.

container-overflow

Escapes container

An element sticks out of its parent's box.

hidden-range

Hidden in a range

An element hides in a middle range of widths but shows on both sides, such as a header button that only disappears on tablets.

small-range

Small-range layout

A layout holds for 5px or fewer between two changes. This is usually a media-query off-by-one, such as min-width: 769px next to max-width: 767px.

text-overflow

Text overflows

A long word, URL or email address runs out of its box.

covered-text

Covered text

A badge, ribbon or label sits on another element's text, or a fixed top bar covers text that scrolling can't reveal.

text-cut

Text cut off

Text runs past the bottom of a box with a fixed height and overflow: hidden.

hidden-submit

Hidden submit button

A form is visible, but its submit button is hidden at that width.

image-distorted

Stretched image

A photo is drawn at a different shape than it has, with no object-fit.

text-clipped

Clipped text

Text is cut off by overflow: hidden.

link-wrapped

Wrapped link

A link or button label of 5 words or fewer breaks onto 2 or more lines.

tiny-text

Tiny text

Text is smaller than --min-font, 12px by default.

How it works

Sweep, bisect, classify

starchy drives headless Chromium through Playwright. It compares how elements sit in rows and boxes, so font rendering noise cannot make it flaky.

  1. Fingerprint

    Load at 1920px. Record how each container's children sit in rows, e.g. 3+3+1, what is visible, and any problems.

  2. Sweep

    Step down 8px at a time, and stop on both sides of every @media breakpoint. When the fingerprint changes, binary-search to the exact pixel.

  3. Capture

    Take before and after screenshots with the changed elements outlined.

  4. Classify

    Match the width against the @media breakpoints in your CSS.

  5. Report

    Write report.html and a fingerprint.json to compare against later.

Media queryThe width matches an @media breakpoint. Expected.
Fluid changeNo media query: flex-wrap, auto-fit or content size. Check it.
ProblemSomething broke at this width.

CI

Run it on every pull request

Run starchy once on a known-good build and commit its fingerprint.json. On every pull request, compare against it.

.github/workflows/layout.yml
name: layout
on: pull_request
jobs:
  starchy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npx playwright install --with-deps chromium
      - run: >-
          npx starchy https://staging.example.com
          --baseline .starchy/fingerprint.json
          --fail-on new
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: starchy-report, path: starchy-report }
  • --fail-on new exits 1 on a new problem or a new layout change. --fail-on problems exits 1 on any problem.
  • The report lists new problems, fixed problems, and layout changes that appeared or disappeared.
  • Pages match by URL. One page compares against a one-page baseline even when the URLs differ, so staging can compare with local.
  • Check several URLs or a whole sitemap.xml in one report. Problems shared by many pages show once.
  • Pages behind a login: pass a Playwright storage state with --storage-state.

Reference

Options

starchy <url-or-file>... [options]. A bare domain gets https://, and localhost gets http://.

FlagDefaultDescription
--max / --min1920 / 320Width range to sweep
--step8Coarse step before bisecting. Lower is slower but more thorough.
--heights900Comma-separated viewport heights, each swept separately
--dpr1Device pixel ratio (affects images and hairlines, not layout)
--min-font12Smallest acceptable text size in px
--ignoreSelectors to skip, e.g. .carousel,.ad-slot
--settle0Extra ms to wait after each resize, for JS-driven layouts
--outstarchy-reportOutput folder
--baselineAn earlier fingerprint.json to compare against
--fail-onnoneproblems or new makes starchy exit 1
--no-screenshotsFaster runs, report without images
--problem-shotsAdd a screenshot of each problem at its first failing width, with the element outlined
--stressDouble the text in repeated items (lists, cards, grids) to find layouts that only hold with short content
--storage-stateA Playwright storage state file, for pages behind a login
